# 📱 Руководство по интеграции мобильного приложения (Android / iOS)

Данное руководство предназначено для разработчиков мобильного клиента **Deep Reader** (Android / Compose / Kotlin / iOS). Оно содержит полный регламент взаимодействия с бэкендом, правила подготовки контекста чтения из EPUB, регламент защиты от сюжетных спойлеров и рекомендации по построению качественного пользовательского интерфейса (UX).

API бэкенда спроектировано строго по **OpenAPI 3.0.3** (FROZEN SPEC: [`docs/specs/02_openapi.yaml`](../specs/02_openapi.yaml)). Все данные передаются в формате `application/json; charset=UTF-8`, имена полей оформлены в **`snake_case`**.

---

## 1. Спецификация REST API

Базовый URL в локальном окружении: `http://10.0.2.2:8080` (для Android Emulator) или `http://<LAN_IP>:8080`.  
В production: `https://api.deepreader.app`.

### 1.1. Интеллектуальный разбор фрагмента (`POST /api/v1/explain`)

Анализирует выделенный фрагмент текста, окружающее предложение и контекст книги. Возвращает глубокий разбор авторского подтекста, фразеологизмов, идиом и стилистических приёмов.

#### Тело запроса (`ExplainRequest`):
```json
{
  "book_id": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
  "selected_text": "clocks were striking thirteen",
  "current_sentence": "It was a bright cold day in April, and the clocks were striking thirteen.",
  "surrounding_context": {
    "sentences_before": [
      "The hallway smelt of boiled cabbage and old rag mats."
    ],
    "sentences_after": [
      "Winston Smith, his chin nuzzled into his breast in an effort to escape the vile wind, slipped quickly through the glass doors."
    ],
    "paragraph": "It was a bright cold day in April, and the clocks were striking thirteen. Winston Smith, his chin nuzzled into his breast in an effort to escape the vile wind, slipped quickly through the glass doors of Victory Mansions, though not quickly enough to prevent a swirl of gritty dust from entering along with him.",
    "chapter_context": "Chapter 1: London, Airstrip One"
  },
  "target_language": "ru"
}
```

#### Спецификация полей запроса:
| Поле | Тип | Обязательное | Описание и ограничения |
| :--- | :--- | :---: | :--- |
| `book_id` | String | Да | SHA-256 хэш файла книги (EPUB) или канонический UUID издания (длина 1–128). Необходим для сегментации кэша. |
| `selected_text` | String | Да | Непосредственно выделенное слово или фраза (длина 1–500 символов). |
| `current_sentence` | String | Да | Полное предложение, внутри которого находится `selected_text` (длина 1–2000). **Никогда не обрезается**. |
| `surrounding_context` | Object | Да | Окружающий контекст. До 2 предложений до (`sentences_before`), до 2 предложений после (`sentences_after`), текущий абзац (`paragraph`, до 4000) и контекст главы (`chapter_context`, до 2000). |
| `target_language` | String | Нет | Двухбуквенный код языка для составления объяснения (`ru`, `en`, `de` и т.д.). По умолчанию `"ru"`. |

#### Успешный ответ `200 OK` (`ExplainResponse`):
```json
{
  "selected_text": "clocks were striking thirteen",
  "contextual_meaning": "Указание на искажённую антиутопическую реальность и 24-часовой формат времени.",
  "phenomenon_type": "metaphor",
  "explanation": "В реальности механические настенные часы отбивают максимум 12 ударов. Удар тринадцатого часа с первых строк погружает читателя в тревожный мир тоталитарного контроля, где нарушены даже законы природы и времени.",
  "stylistic_coloring": "literary",
  "spoiler_alert": false,
  "cached": true,
  "processing_time_ms": 12
}
```

> [!NOTE]
> Обратите внимание на точное имя поля: **`processing_time_ms`** (время обработки запроса в миллисекундах). Если ответ взят из L1/L2 кэша, флаг `cached: true`, а `processing_time_ms` обычно составляет менее 15 мс.

### 1.2. Быстрый контекстный перевод (`POST /api/v1/translate`)

Осуществляет быстрый перевод выделенного слова или абзаца через DeepL API.

#### Тело запроса (`TranslateRequest`):
```json
{
  "text": "clocks were striking thirteen",
  "source_language": "en",
  "target_language": "ru"
}
```

#### Спецификация полей:
- `text` (String, обязательное, 1–5000 символов): переводимый текст.
- `source_language` (String, опционально, 2–10 символов): код языка источника. Если передан `null`, бэкенд и DeepL автоматически определяют исходный язык.
- `target_language` (String, обязательное, 2–10 символов): код целевого языка перевода.

#### Успешный ответ `200 OK` (`TranslateResponse`):
```json
{
  "translated_text": "часы били тринадцать",
  "source_language": "en",
  "target_language": "ru",
  "cached": false
}
```

> [!TIP]
> Даже если клиент передал `source_language: null`, бэкенд сохраняет автоопределённый язык в кэше. При последующих обращениях к кэшу поле `source_language` всегда вернёт фактически распознанный язык (`"en"`).

### 1.3. Проверка состояния сервиса (`GET /api/v1/health`)

Используется для Liveness/Readiness проверок, индикатора сети в приложении и мониторинга доступности L2-кэша.

#### Ответ `200 OK` (`HealthResponse`):
```json
{
  "status": "UP",
  "service": "deep-reader-backend",
  "timestamp": "2026-11-13T12:00:00Z",
  "cache": "CONNECTED",
  "active_llm_provider": "OpenAiAdapter (gpt-4o-mini)"
}
```

В случае недоступности базы данных возвращается `503 Service Unavailable`:
```json
{
  "status": "DOWN",
  "service": "deep-reader-backend",
  "timestamp": "2026-11-13T12:00:00Z",
  "cache": "DISCONNECTED: Connection refused",
  "active_llm_provider": "OpenAiAdapter (gpt-4o-mini)"
}
```

## 2. Правила извлечения контекста из EPUB на клиенте

Для достижения максимального качества анализа и корректной работы серверного кэша мобильный клиент должен соблюдать следующие правила формирования запроса:

### 2.1. Идентификатор книги (`book_id`)
- **Рекомендация:** Вычисляйте **SHA-256 хэш всего EPUB-файла** (или канонический ISBN-13 без дефисов) и передавайте его в качестве `book_id`.
- **Зачем:** Это гарантирует, что тысячи пользователей, читающих одно и то же издание книги, будут попадать в общий L2-кэш бэкенда. Это снижает время ожидания до <15 мс и радикально экономит квоты LLM.

### 2.2. Защита от спойлеров (Strict Spoiler Guardrail)
> [!IMPORTANT]
> **Категорически запрещено передавать в `sentences_after` текст, находящийся за пределами видимого экрана читателя!**
> Если читатель выделил фразу внизу экрана, массив `sentences_after` должен содержать только те предложения, которые пользователь физически видит на текущей странице (или пустой список `[]`).
> Нельзя заглядывать на следующие страницы: системный промпт LLM анализирует только переданный срез, и отсутствие будущих страниц гарантирует невозможность спойлеров сюжетных поворотов или смертей персонажей.

### 2.3. Алгоритм сегментации контекста
1. **`selected_text`**: Точный текст выделенного фрагмента (с сохранением оригинального регистра).
2. **`current_sentence`**: Полное предложение от точки/восклицательного знака до точки, внутри которого содержится выделенный фрагмент.
3. **`sentences_before`**: До 2 предложений перед текущим предложением (только с текущей страницы).
4. **`sentences_after`**: До 2 предложений после текущего предложения (строго не далее границы экрана).
5. **`paragraph`**: Полный текст текущего абзаца из DOM/структуры EPUB.
6. **`chapter_context`**: Название текущей главы или раздела (например, `"Глава 3. Побег"`).

## 4. Обработка ошибок и UX-паттерны в Bottom Sheet

В случае любой нештатной ситуации бэкенд возвращает стандартизированный JSON `ErrorResponse`:
```json
{
  "error_code": "TEXT_TOO_LONG",
  "message": "Выделенный текст вместе с текущим предложением превышает допустимый лимит токенов.",
  "timestamp": "2026-11-13T12:00:00Z",
  "trace_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
  "details": []
}
```

### 4.1. Карта кодов ошибок (`ErrorCode`) и рекомендаций для UX

| HTTP Статус | `error_code` | Причина возникновения | Рекомендация для UI / Bottom Sheet |
| :---: | :--- | :--- | :--- |
| **`400`** | `INVALID_INPUT` | Пустые обязательные поля, длина текста > 5000 символов. | Показать подсказку: «Некорректный запрос». Не давать отправлять пустое выделение. |
| **`400`** | `TEXT_TOO_LONG` | Даже одно выделенное предложение превышает 1000 токенов. | Показать плашку: «Выделен слишком большой фрагмент текста. Пожалуйста, выделите 1–2 фразы». |
| **`422`** | `EMPTY_AI_RESPONSE` | Нейросеть вернула пустой ответ или сбой генерации. | Показать кнопку **«Попробовать снова»** (Retry). Запрос не тарифицируется. |
| **`502`** | `LLM_PROVIDER_ERROR` | Ошибка OpenAI/провайдера (квота, 5xx) или открыт Circuit Breaker. | Показать: «Сервис AI временно недоступен». Предложить быстрый перевод через вкладку DeepL. |
| **`502`** | `TRANSLATION_FAILED` | Ошибка внешнего сервиса перевода DeepL. | Показать кнопку «Повторить» с интервалом в 1–2 секунды. |
| **`504`** | `EXTERNAL_PROVIDER_TIMEOUT` | Превышен таймаут ответа (12с для LLM, 3с для DeepL). | Показать: «Превышено время ожидания ответа сети». Кнопка «Повторить». |
| **`500`** | `INTERNAL_ERROR` | Непредвиденный сбой сервера. | Отобразить короткое сообщение об ошибке и компактный `trace_id` для техподдержки. |

### 4.2. Лучшие практики для клиентского Bottom Sheet (Compose)
1. **Клиентская пре-валидация:** Если выделенный пользователем фрагмент превышает 500 символов, отображайте всплывающую подсказку и не инициируйте сетевой запрос к `/api/v1/explain`.
2. **Скелетон загрузки (Shimmer):** Так как первый вызов LLM без кэша занимает от 800 до 2500 мс, показывайте красивый скелетон заголовка, бейджей и абзаца объяснения.
3. **Отображение `trace_id`:** В нижней части карточки ошибки мелким шрифтом выводите `ID ошибки: {trace_id}` с возможностью скопировать по клику. Это ускоряет трассировку в VictoriaLogs бэкенда.
4. **Офлайн-режим:** При отсутствии интернета не блокируйте чтение: плавно скрывайте выпадающее меню действий или показывайте локальный словарь, если он предзагружен в приложение.
